**Auth:** send `x-api-key: $PARALLEL_API_KEY` on every REST call. The OpenAPI `securitySchemes.ApiKeyAuth` is `in: header, name: x-api-key`, and the SDK sends `x-api-key` (`client.ts`, `authHeaders`). `/v1/responses` and `/v1beta/chat/completions` also accept `Authorization: Bearer <key>`, so stock OpenAI SDKs work. Responses docs use Bearer, and the Source Policy page shows `x-api-key` on `/v1/responses` (https://docs.parallel.ai/resources/source-policy). The MCP servers take `Authorization: Bearer <key>`.

**Egress allow-list (runtime):**
- `api.parallel.ai` (required): every REST API, including Responses, Chat, and SSE streams.
- `search.parallel.ai`: only if Orb uses the hosted Search MCP instead of REST.
- `task-mcp.parallel.ai`: only if Orb uses the hosted Task MCP.
- Not needed at runtime: `platform.parallel.ai` (dashboard and key creation), `docs.parallel.ai`, and `status.parallel.ai`.
- Image Search returns `image_url` and `source_page_url` on arbitrary third-party hosts. Downloading thumbnails or capturing those pages goes through Orb's existing `fetch_url`/`capture_page` egress policy, not Parallel's.
- Webhooks are inbound to a public HTTPS URL, which a local-first macOS app cannot receive. Use polling or SSE instead (see §11).

## 1. Cross-cutting conventions

### 1.1 Base URL, headers, and SDK
- Base URL: `https://api.parallel.ai` (OpenAPI `servers`). The SDK default can be overridden with the `PARALLEL_BASE_URL` env var. The SDK reads `PARALLEL_API_KEY` by default (`src/client.ts`).
- `Content-Type: application/json`. For SSE endpoints, also send `Accept: text/event-stream`.
- SDK defaults: `timeout` 60 s per request (this matters for long `result` calls), `maxRetries` 2, `PARALLEL_LOG` for logging, and `PARALLEL_CUSTOM_HEADERS`. Each method's `RequestOptions` accepts `signal?: AbortSignal` (`src/internal/request-options.ts:67`).
- SDK surface in 1.3.5:
  - `client.search()` and `client.extract()`
  - `client.taskRun.{create, retrieve, events, result, retrieveInput}`
  - `client.taskGroup.{create, retrieve, addRuns, events, getRuns, retrieveRun}`
  - `client.monitor.{create, retrieve, update, list, cancel, events, trigger}`
  - `client.beta.findall.{create, retrieve, cancel, enrich, entitySearch, events, extend, ingest, result, schema}`
  - `client.beta.memory.{retrieve, clear, evict}`
- **The SDK does not cover** Image Search, Responses, Chat, or `tasks/suggest*`. Call those with `fetch`, or use the `openai` SDK with `baseURL: "https://api.parallel.ai/v1"` for Responses. Source: grep of `parallel-web@1.3.5/src`.
- The SDK automatically adds `parallel-beta: findall-2025-09-15` on FindAll calls (`src/resources/beta/findall.ts:52`). This is harmless, because V1 is now the default (https://docs.parallel.ai/findall-api/findall-migration-guide).

### 1.2 `parallel-beta` header values
OpenAPI `ParallelBeta` enum: `mcp-server-2025-07-17`, `events-sse-2025-07-24`, `webhook-2025-08-12`, `findall-2025-09-15`, `search-extract-2025-10-10`, `field-basis-2025-11-25`. Every one of these features is GA now:
- `field-basis-2025-11-25`: Per-Element Basis went GA on 2026-08-24, and the docs say to remove the header. Sources: https://docs.parallel.ai/task-api/guides/access-research-basis and the changelog.
- `findall-2025-09-15`: V1 is the default. The header is accepted but does nothing (FindAll migration guide).
- `mcp-server-2025-07-17`: `mcp_tool_calls` now appears directly in output, and `beta_fields` is deprecated (OpenAPI `TaskRunJsonOutput.beta_fields`).
- `search-extract-2025-10-10`: only applied to the old `/v1beta/search|extract`. New code uses `/v1/*`.

**Recommendation:** send no beta headers. Orb should still tolerate the SDK's FindAll header.

### 1.3 Errors
- Envelope: `{ "type": "error", "error": { "ref_id", "message", "detail?" } }` (OpenAPI `ErrorResponse`). Some routes return FastAPI `HTTPValidationError` instead: `{ detail: [{loc, msg, type}] }`.
- Responses and Chat use the OpenAI envelope: `{error:{message,type,param,code}}`. Responses validation failures return **400**, not 422 (https://docs.parallel.ai/responses-api/openai-compatibility).
- Status codes, from https://docs.parallel.ai/resources/warnings-and-errors:
  - Do not retry: 401 (bad key), 402 (insufficient credit), 403 (invalid processor), 404, 422 (validation).
  - Retry: 408 (sync result timed out; the run is still active), 429 (rate limit over a rolling 60 s window; back off), 500, 502, 503.
- 402 can happen with a positive balance because of **in-flight reservations**. Each running task reserves its estimated cost, and `pro`/`ultra` reserve more. A Task Group checks the balance for the whole batch up front.
- Warnings (non-fatal) arrive in `warnings[]` as `{type: spec_validation_warning | input_validation_warning | warning, message, detail}`.
  - Examples: input fails its schema, too many output fields, a `location` value that is not supported, more than 5 search queries, or `max_results` above 20.
  - Output-schema field names `citations`, `confidence`, `evidence`, `reasoning`, `source`, `sources`, and `source_urls` trigger a warning, because Basis already provides them.

### 1.5 Source policy (shared by Search, Task, Monitor, and Responses)
Source: https://docs.parallel.ai/resources/source-policy and OpenAPI `SourcePolicy`.

`{ include_domains?: string[], exclude_domains?: string[], after_date?: "YYYY-MM-DD" }`
- `include_domains` is a hard allow list. When it is non-empty, `exclude_domains` is ignored.
- Entries can be:
  - plain domains, which also match subdomains (`www.` is normalized away)
  - domain/path prefixes, matched case-sensitively at segment boundaries
  - bare extensions such as `.gov`
- No schemes, ports, query strings, fragments, or `*.` wildcards.
- At most **200 entries combined**.
- `after_date` works on Search only.
- Path prefixes are **not supported in Search `turbo`**.
- The docs warn that filters reduce quality. They recommend steering through `objective` ("prefer official docs") instead.
- Responses maps this onto the OpenAI `web_search` tool `filters.allowed_domains` and `filters.blocked_domains`. If both are set, only the allow list applies.

### 1.6 Basis: citations, reasoning, confidence (Task, FindAll, Monitor, Chat research models)
Sources: https://docs.parallel.ai/task-api/guides/access-research-basis and OpenAPI `FieldBasis`/`Citation`.

```
FieldBasis { field: string, citations: Citation[] (default []), reasoning: string, confidence?: "high"|"medium"|"low"|null }
Citation   { url: string, title?: string|null, excerpts?: string[]|null }
```

- **Text output:** a single entry with `field: "output"`. In deep-research text mode, this lists every site visited, and the report also has inline citations.
- **JSON output:** one entry per top-level field. List fields also get per-element entries such as `key_executives.0`, alongside the parent entry.
- **Auto mode:** nested dot paths such as `industry_overview.growth_cagr` and `market_trends.2.description` (https://docs.parallel.ai/task-api/examples/task-deep-research).

### 1.7 Interactions (follow-ups)
Every Task run returns `interaction_id`. It currently equals the `run_id`, e.g. `trun_...`, per the SSE sample at https://docs.parallel.ai/task-api/task-sse.
- Pass it as `previous_interaction_id` on a new Task run to carry context forward. This works across processors.
- Chat Completions also returns and accepts `interaction_id`.
- A Monitor `event_id` can be passed as `previous_interaction_id` to a follow-up Task (https://docs.parallel.ai/monitor-api/monitor-task).
- Not available for Zero Data Retention (ZDR) orgs (https://docs.parallel.ai/task-api/guides/interactions).
- Responses uses the OpenAI `previous_response_id` instead (https://docs.parallel.ai/responses-api/features/statefulness).

### 1.8 Session IDs (Search and Extract)
- `session_id` is a string of up to 1,000 chars. Reuse one across the Search and Extract calls that belong to the same task. The server echoes it back, or generates one if omitted. Source: https://docs.parallel.ai/search/best-practices.
- Search MCP caps `session_id` at 100 chars.

**Orb mapping:** one `session_id` per Scout run, e.g. `orb_scout_<runId>`.

### 1.9 `client_model`
- Optional string naming the consuming LLM, so Search and Extract can tune output for it. Doc examples: `"claude-opus-5"`, `"gpt-6-astra"`.
- **Orb:** send `client_model: "gpt-6-luna"`.

## 2. Search API: `POST /v1/search`

Sources: https://docs.parallel.ai/api-reference/search/search, https://docs.parallel.ai/search/best-practices, https://docs.parallel.ai/search/modes, https://docs.parallel.ai/search/advanced-search-settings

### Request (`V1SearchRequest`)

| Field | Type | Default / limits |
|---|---|---|
| `search_queries` * | string[] | Required, at least 1. Use 1 to 5 queries of 3 to 6 words, each at most 200 chars. Queries after the 5th are dropped with a warning. 2 to 3 is best. |
| `objective` | string? | Natural-language goal, at most 5,000 chars. Send it together with queries. |
| `mode` | `turbo` \| `fast` \| `basic` \| `advanced` | Defaults to **`advanced`**. |
| `max_chars_total` | int? | Cap on excerpt chars across all results. Default is dynamic. |
| `session_id` | string? | See §1.8. |
| `client_model` | string? | See §1.9. |
| `advanced_settings.source_policy` | SourcePolicy | See §1.5. |
| `advanced_settings.fetch_policy` | `{max_age_seconds? (≥600), timeout_seconds?, disable_cache_fallback=false}` | Default is cached index only. Live fetch adds a lot of latency. |
| `advanced_settings.excerpt_settings.max_chars_per_result` | int? | — |
| `advanced_settings.location` | ISO-3166 alpha-2 | Lowercase, 37 countries supported. Use `gb`, not `uk`. Invalid values are ignored with a warning. |
| `advanced_settings.max_results` | int | Defaults to 10. **Capped at 20**; larger values are reduced with a warning. |

### Modes

| Mode | Latency | $/1k | Notes |
|---|---|---|---|
| `turbo` | ~200 ms | 1 | English and Japanese only. No path-prefix filters. |
| `fast` | ~700 ms | 1 | Recommended default for agents. |
| `basic` | ~1 s | 5 | Longer snippets. Works best with 2 to 3 queries. |
| `advanced` (default) | ~3 s | 5 | Highest quality, for multi-hop or background work. |

Results beyond the first 10 cost an extra $1/1k.

### Response (`V1SearchResponse`)
`{ search_id, session_id, results: [{ url, title?, publish_date? (YYYY-MM-DD), excerpts: string[] /*markdown*/ }], warnings?, usage?: [{name:"sku_search", count}] }`

Results are ordered by decreasing relevance. Errors are 422, 429, and the others in §1.3.

### Gotchas
- There is no snippet/score field. Use `excerpts` (markdown, which can contain "Section Title: …" blocks).
- `publish_date` is often null.
- Parallel's own tool schema (`search_web`, with objective plus 1 to 3 queries and no `site:` operators) is at https://docs.parallel.ai/search/best-practices#search-tool-definition.
- Parallel recommends `fast` as the replacement for OpenAI's built-in `web_search` with small models, and `advanced` with large models (https://docs.parallel.ai/search/migrate-to-parallel).

## 3. Image Search API: `POST /v1/images/search`

Sources: OpenAPI `ImageSearchRequest`/`ImageSearchResponse`, https://docs.parallel.ai/image-search/modes

- **Request:**
  - `search_queries` * (1 to 5, each at most 200 chars)
  - `objective?`
  - `mode?`: `fast` (~1 s, $1/1k) or `advanced` (default, ~3 s, $5/1k)
  - `session_id?`, `client_model?`
  - `advanced_settings?: { location?, max_results? }`. `max_results` defaults to 10, with up to 20 per request at no extra cost.
- **Response:** `{ search_id, session_id, results: [{ title, image_url, source_page_url, width?, height? }], warnings?, usage? }`
- Not in the TS SDK, so call it with `fetch`.
- `image_url` and `source_page_url` are third-party hosts (see the egress note at the top).

## 4. Extract API: `POST /v1/extract`

Sources: https://docs.parallel.ai/api-reference/extract/extract, https://docs.parallel.ai/extract/best-practices, https://docs.parallel.ai/extract/advanced-extract-settings

### Request (`V1ExtractRequest`)
- `urls` * : **up to 20 URLs**. Public pages only, including JS-heavy pages and PDFs. No login-gated content (FAQ).
- `objective?`: at most 5,000 chars. `search_queries?`: at most 5, each at most 200 chars. Either one focuses the excerpts. Without both, Extract returns whole-page markdown.
- `max_chars_total?` (applies to excerpts only), `session_id?`, `client_model?`
- `advanced_settings?`:
  - `fetch_policy`: dynamic by default. `max_age_seconds` is at least 600. `timeout_seconds` is typically 15 to 60 s. `disable_cache_fallback` defaults to false.
  - `excerpt_settings.max_chars_per_result`
  - `full_content`: `false` (default), `true`, or `{max_chars_per_result}`. Full content always starts at the top of the page.
- **Gotcha:** the v1beta top-level fields `excerpts`, `full_content`, and `fetch_policy` sent to `/v1/extract` return **422**. Those fields must go inside `advanced_settings`.

### Response (`V1ExtractResponse`)
`{ extract_id, session_id, results: [{url, title?, publish_date?, excerpts: string[], full_content?: string}], errors: [{url, error_type, http_status_code?, content?}], warnings?, usage? }`

Per-URL failures arrive in `errors[]` with HTTP 200. They are not thrown.

### Cost and latency
- Cost: $1 per 1k URLs. The usage SKU is `sku_extract_excerpts`.
- Latency: 1 to 20 s on the docs pricing page. The marketing page says 1 to 3 s cached and 60 to 90 s live.

Sources:
- https://docs.parallel.ai/task-api/task-quickstart

- https://docs.parallel.ai/task-api/task-sse
- https://docs.parallel.ai/task-api/webhooks
- https://docs.parallel.ai/task-api/mcp-tool-call
- https://docs.parallel.ai/resources/data-connectors
- OpenAPI `TaskRunInput`, `TaskRun`, `TaskRunResult`

### 5.1 Endpoints

| Method | Path | Notes |
|---|---|---|
| POST | `/v1/tasks/runs` | Create a run. Returns **202** with a `TaskRun` (`status: "queued"`). Errors: 401, 402, 403 (invalid processor), 422, 429. |
| GET | `/v1/tasks/runs/{run_id}` | Status only. |
| GET | `/v1/tasks/runs/{run_id}/result?timeout=600` | **Blocks** until the run completes or `timeout` seconds pass (default 600). Returns 408 if still active, and 404 if the run failed or does not exist. |
| GET | `/v1/tasks/runs/{run_id}/events` | SSE progress stream (§5.5). |
| GET | `/v1/tasks/runs/{run_id}/input` | Echoes the `TaskRunInput`. |

**No cancel endpoint exists for Task runs.** The OpenAPI spec and the SDK have none, even though `cancelling` and `cancelled` statuses exist. Aborting on Orb's side only stops waiting: the run continues and **is billed when it completes**. Orb's UI should say this. Source: OpenAPI paths list and `parallel-web/src/resources/task-run.ts`.

### 5.2 Request body (`TaskRunInput`)

| Field | Type | Notes |
|---|---|---|
| `processor` * | string | See §5.3. |
| `input` * | string \| object | Text or JSON. |
| `task_spec` | `{ output_schema, input_schema? }` | If omitted, defaults to the auto schema. |
| `task_spec.output_schema` | `{type:"json", json_schema}` \| `{type:"text", description?}` \| `{type:"auto"}` \| bare string | A bare string is treated as a text schema. `auto` gives deep-research-style output **only on `pro` and above**, and auto is the default for the `pro`/`ultra` families. |
| `source_policy` | SourcePolicy | §1.5 |
| `previous_interaction_id` | string | §1.7 |
| `metadata` | `{[k]: string}` | Keys at most 16 chars, values at most 512 chars. |
| `mcp_servers` | `[{type:"url", url, name, headers?, allowed_tools?}]` | At most 10 servers, Streamable HTTP only, tools only. For OAuth servers, pre-mint a Bearer token. `lite` and `core` make at most 1 tool call. |
| `advanced_settings` | `{ location?: ISO2, data_sources?: {free: string[], pay_per_use: string[]} }` | Free connectors: `pubmed`, `clinical_trials`, `chembl`, `biorxiv`, `npi_registry`, `cms_coverage`. Pay-per-use: `carbonarc`. A connector name must not collide with an `mcp_servers` name. A connector not yet enabled for the org gets a 422. |
| `enable_events` | bool | Records detailed progress events. Defaults to true for `pro` and above. It cannot be enabled after creation. |
| `webhook` | `{url, event_types:["task_run.status"]}` | §11 |
| `memory_scope_key` | string | Opt-in application memory (§10). |

**Schema limits** (https://docs.parallel.ai/task-api/guides/specify-a-task):
- The root must be `type: object` with `properties` and no root `anyOf`.
- All fields should be required. Use `["string","null"]` for an optional field. Set `additionalProperties: false`.
- Nesting depth at most 5. At most 100 properties. At most 500 enum values.
- Task spec at most 15,000 chars. **Spec plus input at most 25,000 chars.**
- Deep research input should stay under 15,000 chars.
- Unsupported keywords: `format`, `pattern`, `min*`/`max*`, `uniqueItems`, `contains`, and similar.

### 5.4 Task run object and result
- `TaskRun`: `{ run_id, interaction_id, status: queued|action_required|running|completed|failed|cancelling|cancelled, is_active, warnings?, error?, processor, metadata?, taskgroup_id?, created_at, modified_at }`
- `TaskRunResult`: `{ run, output }`
  - `output` is `TaskRunTextOutput {type:"text", content: string, basis, mcp_tool_calls?}`
  - or `TaskRunJsonOutput {type:"json", content: object, basis, mcp_tool_calls?, output_schema? (populated for auto)}`
- `mcp_tool_calls[]`: `{tool_call_id, server_name, tool_name, arguments (JSON string), content?, error?}`. Data-connector calls appear here too, with `server_name` set to the connector name.

### 5.5 SSE events: `GET /v1/tasks/runs/{id}/events`
Event types:
- `task_run.state`: the first and last event. The final one includes the full `output` when the run completed.
- `task_run.progress_stats`: `{source_stats:{num_sources_considered, num_sources_read, sources_read_sample[]}, progress_meter: 0–100}`
- `task_run.progress_msg.{plan|search|result|tool_call|exec_status|extract}`: `{message, timestamp}`. Search messages are prefixed `Objective:` or `Query:`. They are emitted on `base` and above; `lite` emits few reasoning messages.
- `error`

Behavior:
- **The stream stays open up to 570 s at most**, and closes earlier once the run is non-active. Reconnect in a loop.
- It is **not resumable** (no cursor). Reconnecting to an active run replays all progress messages plus the current stats. Connecting to a finished run sends a single state event with the output.
- Runs without `enable_events` get less frequent events.

### 5.6 Recommended Orb wait strategy
1. Create the run with `enable_events: true`.
2. Loop:
   - Open the SSE stream (SDK `client.taskRun.events(id, {signal})`) and forward `progress_msg`/`progress_stats` to the UI.
   - When the stream closes, if the last `task_run.state` is terminal, finish. Otherwise reconnect, deduping messages by timestamp and text.
3. Fallback: poll `GET /runs/{id}` every 5 to 15 s and use exponential backoff for long processors. Or loop on `GET /result?timeout=25` and treat 408 as "still running". The docs' TS sample uses `timeout: 25` (https://docs.parallel.ai/task-api/guides/interactions). Keep each HTTP request under the SDK's 60 s client timeout, or raise it per call.
4. On AbortSignal: close the stream and stop polling. Mark the card "detached (still running on Parallel, will be billed)". Optionally store the `run_id` so the user can re-attach later.

### 5.7 Task Groups (batch): `/v1/tasks/groups`
Source: https://docs.parallel.ai/task-api/group-api

- `POST /v1/tasks/groups` `{metadata?}` returns `{taskgroup_id, status:{num_task_runs, task_run_status_counts, is_active, status_message, modified_at}, metadata, created_at}`.
- `POST /v1/tasks/groups/{id}/runs` `{default_task_spec?, inputs: TaskRunInput[] (≤1,000 per POST)}` returns `{status, run_ids[], run_cursor, event_cursor}`.
- `GET /v1/tasks/groups/{id}` gives the aggregate status.
- `GET /v1/tasks/groups/{id}/events?last_event_id&timeout` is an SSE stream of `task_group_status` and `task_run.state` events. It is **resumable** via `event_id` and stays open up to 1 h while any run is active.
- `GET /v1/tasks/groups/{id}/runs?include_input&include_output&status&last_event_id` streams the runs over SSE, with no pagination.
- `GET /v1/tasks/groups/{id}/runs/{run_id}` returns one run's status. Fetch results from `/v1/tasks/runs/{id}/result`.
- Each input counts toward the 2,000/min quota. The balance for the whole batch is checked up front (402 risk).

## 6. Responses API (OpenAI Responses-compatible): `POST /v1/responses`

Sources:
- https://docs.parallel.ai/responses-api/responses-quickstart
- https://docs.parallel.ai/responses-api/openai-compatibility
- https://docs.parallel.ai/responses-api/features/streaming-events
- https://docs.parallel.ai/responses-api/features/citations
- https://docs.parallel.ai/responses-api/features/web-search-tool
- https://docs.parallel.ai/responses-api/features/mcp-tools
- https://docs.parallel.ai/responses-api/examples/research-subagent

### Request
- `model: "parallel"` is the only accepted value.
- `input`: a string or messages; text only.
- `reasoning.effort`: `low` ($10/1k, ~5 to 10 s), `medium` (default, $50/1k, ~15 to 20 s), or `high` ($250/1k, ~30 to 60 s; set the client timeout to at least 120 s).
- `instructions`. `input` plus `instructions` must total at most 20,000 chars.
- `previous_response_id`, `stream`, `metadata` (at most 16 keys).
- `text.format`: `{type:"json_schema", name, schema}` for structured output. JSON is returned encoded in the output text.
- `tools`:
  - `web_search` with `filters` (allow/block domains), at most one per request.
  - `mcp` tools (at most 10), with `require_approval: "never"` required.
  - All other tools are ignored.
- `data_sources: {free, pay_per_use}` works only with `medium` or `high` effort.

**Rejected (400):** `background: true` (use the Task API for long work), multimodal input, any model other than `parallel`, `data_sources` with `low` effort, and similar.

**Ignored:** `temperature`, `max_output_tokens`, `tool_choice`, `store` (responses are always stored), and similar.

### Response
OpenAI `Response`. `output[]` contains:
- one `web_search_call` item per search or page read (`action: {type:"search", queries[]}` or `{type:"open_page", url}`)
- `mcp_list_tools` and `mcp_call` items
- a `message` item whose `content[0]` is `{type:"output_text", text, annotations:[{type:"url_citation", url, title, start_index, end_index}]}`

`usage` holds approximate token counts; billing is per request.

### Streaming
- Events follow the standard OpenAI sequence. **The answer text arrives as a single `response.output_text.delta`** once research finishes, not token by token.
- `response.created` and `response.in_progress` come early, and the `web_search_call` "searching" events can drive progress UI.
- Citations arrive as `response.output_text.annotation.added`, and `response.completed` carries the full object.

### Statefulness
- `previous_response_id` works for follow-ups. Each turn does fresh research.
- Disabled for ZDR orgs.

**Why it matters for Orb:** this is Parallel's recommended "research subagent" tool. The orchestrator gets a cited, synthesized answer in seconds and can abort with a plain HTTP abort. Because the call is synchronous, aborting the request is the closest thing to cancellation. Parallel bills only successful responses, so an aborted request is unlikely to be billed, but the docs do not state this.

### 8.2 Create body (`FindAllRunInput`)
- `objective` * (string)
- `entity_type` * (free string, e.g. `"companies"` or `"people"`)
- `match_conditions` * : `[{name, description}]`. These are boolean criteria.
- `generator` * : `preview` \| `base` \| `core` \| `pro`
- `match_limit` * : 5 to 1,000. For `preview` it is 5 to 10, and it counts *candidates evaluated*.
- `exclude_list?` : `[{name, url}]`, at most 10,000 entries
- `metadata?`, `webhook?` (`{url, event_types}`), `memory_scope_key?`

Enrichments are **not** part of the create body (the OpenAPI spec has no field for them). Add them afterwards with `/enrich`. They run on all current and future matches, and adding one to a terminal run requeues it.

### 8.3 Generators and pricing

| Generator | Fixed | Per match | Use |
|---|---|---|---|
| `preview` | $0.10 | $0 | 5 to 10 candidates. Validate the schema first. Cannot be extended. |
| `base` | $0.25 | $0.03 | Broad queries, many matches, under 20 needed. |
| `core` | $2.00 | $0.15 | Specific queries, 20 to 50 matches. |
| `pro` | $10.00 | $1.00 | Rare or hard-to-find matches. |

- Enrichments add Task processor price × number of matches, per enrichment.
- Extend charges no new fixed fee.
- Cancel still bills work that already completed.
- Latency is 10 s to 2 h (the marketing page says 10 min to 1 h).

### 8.4 Lifecycle, candidates, and events
- **Statuses:** queued, running, completed, failed, cancelled. `action_required` and `cancelling` exist in the schema but FindAll does not emit them.
- **Termination reasons:** `match_limit_met` (the only one that can be extended), `low_match_rate`, `candidates_exhausted`, `error_occurred`, `timeout`, `user_cancelled`, `insufficient_funds`.
- **Candidate:** `{candidate_id, name, url, description?, match_status: generated|matched|unmatched|discarded, output?: {[field]: {value, type:"match_condition", is_matched} | {value, type:"enrichment"}}, basis?: FieldBasis[]}`
- **SSE event types:** `findall.status` (a heartbeat every 10 s and on status change), `findall.candidate.{generated, matched, unmatched, discarded (not currently produced), enriched}`, `findall.schema.updated`, and `error`.
- Resume the stream with `last_event_id`, which is also returned by `/result`.
- **Webhook event types:** `findall.candidate.{generated, matched, enriched}` and `findall.run.{completed, cancelled, failed}`.
- **Real cancellation exists:** abort maps to `POST /cancel`.

### 8.5 Entity Search vs FindAll
- Entity Search is synchronous (1 to 3 s), costs $5/1k, and returns `name`/`url`/`description` with no verification or citations. It is optimized for recall and has no pagination.
- FindAll verifies each candidate against the match conditions, and returns basis/citations and enrichments.
- Entity Search scope is professional context only, not consumer profiling.

## 11. Webhooks (Task, FindAll, Monitor): mostly not applicable to Orb

Source: https://docs.parallel.ai/resources/webhook-setup

- Follows Standard Webhooks (Svix). Headers: `webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64>` (space-delimited when there are several).
- HMAC-SHA256 over `id.timestamp.body`. The key is the base64 decoding of the secret with the `whsec_` prefix stripped. The secret is per account (Settings → Webhooks).

- **A local-first macOS app has no public endpoint, so Orb should not use webhooks.** Use SSE or polling while the app is open, and on launch re-sync any runs that were in flight.

## 14. Proposed Orb integration

### 14.1 Module layout (suggested)
- `parallel/client.ts`: a single `new Parallel({ apiKey: env.PARALLEL_API_KEY, timeout: 90_000, maxRetries: 2 })`.
  - Add thin `fetch` wrappers for `/v1/images/search`, `/v1/responses`, and `/v1beta/tasks/suggest*` with the same `x-api-key`. Keep the host allow-list as `api.parallel.ai`.
  - If `PARALLEL_API_KEY` is missing, do not register the tools. Fall back to the existing providers.
- `parallel/runs.ts`: a long-run manager for Task, Task Group, and FindAll. It handles:
  - AbortSignal plumbing and progress callbacks
  - persisting `{kind, id, boardId, cardIds, createdAt, processor, estCost}` to local storage, so runs can be re-attached after an app restart
  - mapping results to cards (§14.4)
- `parallel/cost.ts`: a static price table (§0) to estimate cost before launching. Use it to decide whether to ask for confirmation (§14.5).

### 14.2 Registering Search as a `web_search` provider
Add a `parallel` provider beside openai, brave, and tavily that implements the existing `web_search` provider interface:

```ts
// provider: 'parallel'
async function parallelWebSearch(q: { query: string; queries?: string[]; objective?: string;
  maxResults?: number; freshnessAfter?: string; includeDomains?: string[]; excludeDomains?: string[];
  depth?: 'turbo'|'fast'|'basic'|'advanced'; country?: string }, ctx: { signal: AbortSignal; sessionId: string }) {
  const res = await parallel.search({
    objective: q.objective ?? q.query,
    search_queries: (q.queries?.length ? q.queries : [q.query]).slice(0, 5),
    mode: q.depth ?? 'fast',                       // Scout default; 'advanced' for root/background
    session_id: ctx.sessionId, client_model: 'gpt-6-luna',
    advanced_settings: {
      max_results: Math.min(q.maxResults ?? 10, 20),
      location: q.country?.toLowerCase(),
      source_policy: (q.includeDomains || q.excludeDomains || q.freshnessAfter) ? {
        include_domains: q.includeDomains ?? [], exclude_domains: q.excludeDomains ?? [],
        after_date: q.freshnessAfter } : undefined,
    },
  }, { signal: ctx.signal });
  return res.results.map(r => ({ url: r.url, title: r.title ?? r.url, snippet: r.excerpts.join('\n\n'),
    publishedAt: r.publish_date ?? undefined, provider: 'parallel' }));
}
```

Notes:
- If `turbo` is used, strip path prefixes from the domain filters first. Keep the total filter entries at 200 or fewer.
- Excerpts are markdown and dense. Truncate each result to about 1,500 to 3,000 chars for the LLM, and keep the full text so `read_source`/`place_card` can quote it.
- Provider-selection default: when `PARALLEL_API_KEY` is set, make `parallel` the default `web_search` provider with `mode: 'fast'` ($0.001 per call, ~700 ms).

### 14.3 Agent tools (Scout and root agent)
JSON-schema-ish. `*` marks a required parameter. All tools take an implicit `ctx.signal`, `ctx.sessionId`, and `ctx.onProgress`.

#### 1. `web_search` (existing tool; the Parallel provider is added)
Scout continues to use the existing `web_search`; only the backend changes. Optionally expose these extra parameters when the provider is `parallel`:
- `objective` (string)
- `queries` (string[], 1 to 3)
- `depth` (`fast` | `advanced`)
- `after_date` (YYYY-MM-DD)
- `include_domains` and `exclude_domains` (string[])

The tool is sync. Each result can become a `source` card.

#### 2. `parallel_extract`
Can replace or augment `fetch_url`/`read_source` for public pages.
```
{ urls*: string[1..20], objective?: string, queries?: string[≤5], full_content?: boolean=false,
  fresh?: boolean=false /* sets fetch_policy.max_age_seconds=600 */ }
```
- Calls `POST /v1/extract` (sync).
- Return the per-URL excerpts. Include `full_content` only when the caller asks, because it can run to tens of thousands of tokens.
- Report `errors[]` per URL so the agent can fall back to `fetch_url`/`capture_page`, e.g. for login-gated pages or screenshots.
- Results can feed `source`/`quote` cards. The `publish_date` and `title` fill card metadata.

#### 3. `image_search`
```
{ queries*: string[1..5], objective?: string, mode?: 'fast'|'advanced'='fast', max_results?: int≤20=10, country?: string }
```
- Calls `POST /v1/images/search` (sync).
- Returns `[{title, image_url, source_page_url, width, height}]`.
- Maps to `image` cards: `url = image_url`, `summary = title`, `source = source_page_url`. Download goes through the existing image fetch and egress policy.

#### 4. `web_answer` (Responses API; the research subagent)
```
{ question*: string /* complete, self-contained, all constraints */, effort?: 'low'|'medium'|'high'='low',
  schema?: object /* JSON Schema → text.format json_schema */, include_domains?: string[], exclude_domains?: string[],
  follow_up_of?: string /* previous response id */ }
```
- Calls `POST /v1/responses`. Use `stream: true` and turn `web_search_call` items into progress events ("searching: <queries>", "reading: <url>").
- Timeout: 30 s for low, 60 s for medium, 120 s for high. Abort with the AbortController.
- Returns `{answer, citations: [{url, title, span}], searches: [...], response_id}`.
- **Card mapping:** one `quote`/note card for the answer, with its summary set to the answer. Create one `source` card per distinct cited URL; its summary is the cited sentence span, `text.slice(start_index, end_index)`. Link the answer card to the source cards.
- Cost: $0.01, $0.05, or $0.25 per call.

#### 5. `deep_research` (Task API, async)
```
{ input*: string | object, processor?: 'lite'|'base'|'core'|'core2x'|'pro'|'ultra'|'ultra2x'|'ultra4x'|'ultra8x'='pro',
  output?: { kind: 'auto'|'text'|'json', description?: string, json_schema?: object } = {kind:'auto'},
  include_domains?: string[], exclude_domains?: string[], country?: string,
  data_sources?: { free?: ('pubmed'|'clinical_trials'|'chembl'|'biorxiv'|'npi_registry'|'cms_coverage')[], pay_per_use?: ('carbonarc')[] },
  follow_up_of?: string /* previous interaction_id */, wait?: boolean=true }
```
- Calls `POST /v1/tasks/runs` with `enable_events: true` and `metadata: {orb_board, orb_card}`. Then follows the §5.6 loop: stream SSE, reconnect every 570 s or less, and poll as a fallback.
- **Progress:** forward `progress_meter` (0 to 100), the sources-read count, and `plan`/`search` messages through `ctx.onProgress`.
- **Abort:** stop listening and mark the run detached. There is **no server cancel**, so the run is still billed. Store `run_id` so `research_status` can re-attach.
- **Non-blocking mode:** with `wait: false`, return `{run_id, interaction_id, eta}` immediately so the agent can continue. A placeholder "researching…" card shows progress and fills in when done.
- **Card mapping:**
  - `text` output gives a report card containing the markdown.
  - `json`/`auto` output gives a structured card containing the content.
  - In both cases, create `source` cards from the **deduplicated** URLs in `basis[].citations`. Each card's summary is the first excerpt; fall back to `basis.reasoning` for the field. Attach `confidence` as a badge and list each field path that the source supports.
  - Low-confidence fields are flagged in the UI.
  - Cap auto-placed source cards at about 12, ranked by how many fields cite them, and keep the rest in the card's "all citations" drawer.

#### 6. `research_status` / `research_result`
```
{ run_id*: string }
```
- `GET /v1/tasks/runs/{id}`, or the FindAll equivalent.
- Lets the agent re-attach to detached runs or check whether they have finished. Returns status, progress, and the result if it is complete.

#### 7. `batch_enrich` (Task Group)
```
{ rows*: (string|object)[1..1000], output_json_schema*: object, processor?: 'lite'|'base'|'core'='base',
  include_domains?: string[] }
```
- Calls `POST /v1/tasks/groups`, then `POST .../runs` with `default_task_spec`. Use the resumable group SSE `/events` for progress (n completed of N). Fetch each result from `/v1/tasks/runs/{id}/result`, or use `GET .../runs?include_output=true`.
- Abort means stop listening. The runs continue and are billed. There is no group cancel.
- Maps to a table card (rows × fields), with citations per cell from `basis`.

#### 8. `find_entities` (FindAll)
```
{ objective*: string, entity_type?: string, match_conditions?: {name, description}[] /* if omitted, call ingest */,
  generator?: 'preview'|'base'|'core'|'pro'='preview', match_limit?: int=10,
  enrichments?: { processor?: 'lite'|'base'|'core', json_schema: object }[], exclude?: {name,url}[] }
```
Flow:
1. If no conditions were given, call `ingest`. Optionally show the conditions to the user.
2. `POST /runs`.
3. For each enrichment, call `POST /enrich`.
4. Stream `/events` and resume via `last_event_id`. Progress comes from `metrics` (generated and matched counts). Each `candidate.matched` event can appear live as an entity card.
5. On a terminal status, call `GET /result`.

- **Abort** calls `POST /v1beta/findall/runs/{id}/cancel`, which is a real cancellation. Work already done is still billed.
- **Card mapping:** one entity card per matched candidate. `url` is the candidate URL. `summary` is the description plus the match values and enrichment values. Citations come from `basis`. Each card is a "source" card with field badges.
- `find_entities_extend {findall_id, additional_match_limit}` is allowed only when `termination_reason == match_limit_met`.

#### 9. `entity_search` (sync)
```
{ entity_type*: 'people'|'companies', objective*: string, limit?: 5..1000=25 }
```
- Calls `POST /v1beta/findall/entity-search` ($0.005, 1 to 3 s).
- Maps to lightweight entity cards (name, url, description), marked "unverified".

#### 10. `watch_topic` / `list_watches` / `watch_events` / `stop_watch` (Monitor; root agent only, user-initiated)
- `watch_topic {query*, frequency='1d', processor='lite', include_domains?, output_json_schema?, backfill?=false}` calls `POST /v1/monitors` with `metadata: {orb_board}`.
- `watch_events {monitor_id*, since_cursor?}` calls `GET /v1/monitors/{id}/events`. Each event becomes a note card with its basis citations as source cards.
- On app launch, Orb pulls new events for the board's monitors. There are no webhooks.
- `stop_watch` calls `POST /cancel`.
- These monitors incur ongoing cost. Show the projected monthly cost, e.g. 1d `lite` is about 30 × $0.003 = $0.09 per month.

#### 11. Optional extras
- `research_memory {query, kind?}` calls `POST /v1beta/memory/retrieve` with `memory_scope_key="orb:<board>"`, to reuse past runs.
- `suggest_task_spec {intent}` calls `POST /v1beta/tasks/suggest`, to help the agent build JSON schemas for `deep_research` and `batch_enrich`.

### 14.4 General mapping from results to cards (citations)
- **Search and Extract result:** `source` card with `url = result.url`, `summary` = the first excerpt trimmed to about 300 chars (or an LLM-written summary per the existing `place_card` contract), `title`, and `publishedAt = publish_date`.
- **Quote card:** a verbatim span from `excerpts[]` or `basis.citations[].excerpts[]`. The `url` is the citation URL. Store `provenance: {provider: "parallel", kind: "search"|"extract"|"task"|"findall"|"monitor"|"responses", id: search_id|extract_id|run_id|findall_id|response_id, field?: basis.field, confidence?}`.
- **Responses citations:** `url_citation` annotations carry `start_index`/`end_index` into the answer text. Use that span as the quote card's summary, and link it to the answer card.
- **Dedupe:** collapse cards across tools by normalized URL.

### 14.5 Persona snippet (Scout and root agent)

```
## Web research tools (Parallel)
Pick the cheapest tool that can answer reliably. Costs are approximate per call.

- web_search (Parallel, mode=fast, ~0.7s, $0.001): default for finding pages. Always give a
  one-sentence `objective` plus 1-3 short keyword queries (3-6 words each, no site: operators).
  Results are already dense excerpts, so read them before fetching pages.
  Use depth=advanced (~3s, $0.005) for hard multi-hop lookups. Use after_date for recency.
  Use include_domains only when the answer must come from those sites.
- parallel_extract ($0.001/URL, 1-20s): read specific URLs. Pass an objective so you get focused
  excerpts. Ask for full_content only when you need the whole document.
  Fall back to fetch_url / capture_page for login-gated pages, screenshots, or failed URLs.
- image_search ($0.001, ~1s): find images for image cards. Always keep source_page_url as attribution.
- web_answer (Responses API): a cited, synthesized answer to ONE complete, self-contained question.
  effort=low (~5-10s, $0.01) for facts; medium (~15-20s, $0.05) for multi-hop; high (~30-60s, $0.25)
  only for hard synthesis. Ask the full question in one call. Run independent questions in parallel.
  Prefer this over many search+read loops when the user wants an answer, not a pile of sources.
- deep_research (Task API, async, minutes): analyst-grade reports or structured JSON with
  per-field citations and confidence.
  lite/base ($0.005-0.01, ~1 min) for 1-5 simple fields; core ($0.025, ~1.5-5 min) for up to 10
  cross-checked fields; pro ($0.10, ~3-10 min) for exploratory deep research (default for reports);
  ultra ($0.30, ~4-25 min) for hard multi-source reports; ultra2x-8x ($0.60-$2.40, up to 2h) only
  when the user explicitly asks for maximum depth.
  These runs cannot be cancelled server-side once started; stopping only detaches.
  Use wait=false and keep working; check back with research_status.
  To continue an earlier report, pass follow_up_of=<interaction_id>.
  Never put citations/sources/confidence fields in a JSON schema. They come back automatically.
- batch_enrich (Task Group): the same question for many rows (companies, papers, people).
  Use base unless rows need cross-checking (core).
- entity_search ($0.005, ~2s): a quick unverified list of companies or people.
- find_entities (FindAll): a verified list matching explicit criteria. ALWAYS start with
  generator=preview ($0.10). Then base ($0.25 + $0.03/match), core ($2 + $0.15/match), or pro
  ($10 + $1/match) for rare matches. Add enrichments for extra columns. Cancel when you have enough.
- watch_topic (Monitor): only when the user asks to track something over time.
  It costs money on every scheduled run, even when Orb is closed.

Budget rules: ask the user before any single action estimated above $0.50 (ultra or higher,
FindAll core/pro, Task Groups over 50 rows, any Monitor). Prefer web_search -> parallel_extract ->
web_answer -> deep_research, in that order of escalation.
Every factual card you place must carry the URL it came from.
```

### 14.6 Settings and config
- Env/keychain key: `PARALLEL_API_KEY`. Optional overrides: `PARALLEL_BASE_URL`, `PARALLEL_SEARCH_MODE` (default `fast`), `PARALLEL_MAX_PROCESSOR` (default `ultra`), and `PARALLEL_CONFIRM_ABOVE_USD` (default 0.5).
- Egress allow-list: `api.parallel.ai`. Add `search.parallel.ai` and `task-mcp.parallel.ai` only if the MCP route is used.
- On app start, re-attach persisted active runs:
  - Task: `GET /v1/tasks/runs/{id}`, then `/result` if completed.
  - FindAll: `GET /result`.
  - Monitors: `GET /events`.
